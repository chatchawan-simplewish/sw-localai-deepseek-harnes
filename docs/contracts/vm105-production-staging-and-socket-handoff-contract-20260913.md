## Host supervisor

The selected implementation uses one root transient service invoked with `systemd-run --wait --pipe`. The outer launcher passes a separately supplied credential read descriptor directly as `systemd-run` standard input without reading or copying it; arbitrary descriptor inheritance is not used or claimed. Inside the unit, the service reads a bounded strict version-1 credential document, writes it once into a fresh close-on-exec anonymous pipe for the contained worker, and closes the write end before forking. No complete memory-erasure proof is claimed.

The unit parent retains host networking only to:

1. Validate every non-secret binding and create one close-on-exec `AF_UNIX` stream socket pair.
2. Fork the worker and wait for its namespace-ready signal before opening a network connection.
3. Use the already bound numeric action-time gateway IP and port without DNS and open exactly two connected TCP streams in fixed order: chat first, durable ACK second.
4. Send one `sendmsg` payload, exactly `VM105_GATEWAY_FDS_V1 chat ack`, with exactly those two `SCM_RIGHTS` descriptors in that order. It must send no third network descriptor.
5. Close its copies of both TCP descriptors and the control endpoint immediately after handoff. Any send or worker failure closes all supervisor-owned descriptors and stops without reconnect, retry, discovery, or destination fallback.

No host-network listener is permitted. The earlier whole-unit `PrivateNetwork=yes` assumption is replaced: the service parent retains host networking only for the two fixed numeric-peer connections. The worker calls `unshare(CLONE_NEWNET | CLONE_NEWPID)`, raises only loopback, proves the network namespace differs, then forks. The namespace PID-1 child alone creates a private mount namespace, mounts a fresh `/proc`, self-bind-mounts and remounts `/var/tmp` read-only, preserves only its assigned runtime directory as writable before remounting `/run` read-only, proves its PID namespace differs and its namespace PID is 1, closes every descriptor outside its allowlist, and drops supplementary groups, GID, and UID before running the contained entry. The intermediate namespace process closes all descriptors and only reaps PID 1. The worker receives only the control endpoint, credential read descriptor, and bounded receipt channel before the two gateway sockets arrive.

The transient unit name must match only `vm105-dsh-<32 lowercase hexadecimal characters>.service`. Its exact capability bound is `CAP_SYS_ADMIN CAP_NET_ADMIN CAP_SETUID CAP_SETGID CAP_CHOWN`. Its hardening properties are `NoNewPrivileges=yes`, `UMask=0077`, `ProtectSystem=strict`, `ReadOnlyPaths=/run /tmp`, `ReadWritePaths=/var/tmp /run/<validated-unit-name-without-.service>`, `ProtectHome=yes`, `PrivateDevices=yes`, `RuntimeDirectory=<validated-unit-name-without-.service>`, `RuntimeDirectoryMode=0700`, `RuntimeDirectoryPreserve=no`, `ProtectControlGroups=yes`, `ProtectKernelTunables=yes`, `ProtectKernelModules=yes`, `ProtectKernelLogs=yes`, `LockPersonality=yes`, `RestrictSUIDSGID=yes`, `RestrictRealtime=yes`, `RestrictAddressFamilies=AF_UNIX AF_INET AF_INET6`, `TasksMax=32`, `LimitCORE=0`, `KillMode=control-group`, `Delegate=no`, `Restart=no`, `TimeoutStartSec=15s`, `RuntimeMaxSec=600s`, and `TimeoutStopSec=10s`. ## Contained launcher and relay

`scripts/Invoke-VM105FinalClient.py` provides `receive_gateway_sockets` and `TwoRequestRelay.from_socket_handoff` for a Linux launcher to use after entering the private network namespace.

The receiver requires Unix `SCM_RIGHTS` with atomic `MSG_CMSG_CLOEXEC`, the exact payload, zero returned receive flags, only `SOL_SOCKET`/`SCM_RIGHTS` ancillary records, and exactly two non-inheritable `AF_INET`/`AF_INET6` TCP stream sockets. It assigns descriptor zero to chat and descriptor one to durable ACK. Both peers must equal the externally supplied action-time gateway IP and port. Platforms without every required primitive fail before reading the control socket. The relay constructor closes the contained control endpoint after the one receive attempt, whether it succeeds or fails.

The existing relay then binds only its namespace-local `127.0.0.1` listener at the exact numeric port parsed from the bound `relayOrigin`; an unavailable port or any actual-origin mismatch fails before DSH starts. The network claim is limited to IP/TCP isolation. Linux pathname `AF_UNIX` sockets remain reachable across this boundary and are an explicit residual, so this source must not be presented as general IPC isolation. The relay's first accepted request uses the chat descriptor and its second accepted request uses the ACK descriptor. Each claimed socket receives the relay timeout before an `HTTPConnection` adopts it; the relay does not call `connect`, resolve another host, or replace either stream. Existing tuple equality, ACK-before-output, third-request denial, zero retry, bounded shutdown, and cleanup rules remain in force.

Before the locked output commit, malformed metadata, truncation, an unexpected ancillary record, a wrong descriptor count, a wrong peer, a duplicate assignment, or protocol failure closes every received descriptor and releases no model output. After that commit, an additional request receives HTTP 403 without changing the successful transaction; normal completion or shutdown still closes the descriptors. No retry is permitted.

The production key must be supplied through the separate read descriptor used as `systemd-run --pipe` standard input only after the coordinator binds the opaque key identity/reference and schema `v1-refs`. The accepted strict document is canonical UTF-8 JSON with one trailing newline: `{"refs":{"<bound-reference>":"<value>"},"version":1}\n`. The reference must use the accepted POSIX-style shape and the value must be nonempty and header-safe. The contained decoder reads it once from the worker pipe and rejects any extra key, reference mismatch, noncanonical encoding, oversize input, carriage return, NUL, or unsafe value. Passing the key into the relay and HTTP authorization header necessarily creates an immutable string. The supported claim is only that the key remains transient within the contained process and is not persisted in argv, environment, a committed file, logs, receipts, or the retained root; no wipe or complete memory-erasure proof is claimed. A sanitized `credentialExposed:false` receipt attests only to those named persistence and exposure surfaces.

DSH does not receive the production key. Its credentials-local adapter receives a separate close-on-exec pipe containing a fixed nonsecret dummy version-1 credential document. A separate nonsecret patch points credentials-local to that pipe with watching disabled, binds `llm-pi-ai` to the exact bound loopback relay origin and `agent/normal`, disables retry and direct-provider surfaces, and disables tool-producing rows. The relay alone replaces the outbound authorization value with the decoded production key. The contained entry invokes the exact staged Node and DSH headless paths under the systemd runtime directory and rejects a relay-origin mismatch before starting the process.

These concrete topology reconstruction, group-readable symlink-aware sealing, decoder, dummy-credential, patch, and DSH-entry adapters do not activate the source. The pnpm/headless topology receipt hashes are bound, while `ACCEPTED_LIVE_BINDINGS` and current service selectors remain unbound.
