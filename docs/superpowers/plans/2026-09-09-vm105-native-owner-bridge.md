## Private transport

Use a Unix socket under a verified candidate-private directory (0700 parent,0600 socket, same expected owner). Refuse unexpected/existing paths, symlinks or unsafe ancestors; never remove unknown objects. Verify bound socket identity before removing only the owned socket on disposal. One conversation and at most one begin per plugin lifetime; no automatic retry. The permissions protect the VM account boundary, not uniquely a human against other same-UID processes.

The client runs only in the owner's private SSH terminal outside Codex output/transcripts. It must reject noninteractive captured execution for authentication. Escape terminal control sequences; hide both text and secret input. Never auto-open links. Device choice uses the native `device_code` option through the ordinary native select prompt; browser choice is unavailable until its separate callback requirements are verified. No guessed notice fields: use retained source mappings and render bounded private native notices as data.

Finite JSON-line messages: client begin/answer/decline/cancel; server notice/prompt/withdraw/result/error. Prompt IDs correlate one outstanding response; strict schemas reject unknown fields, malformed/oversized frames, unsolicited/duplicate answers and invalid option IDs. Fix frame/queue/time bounds, check backpressure and close on violation. Never send credential records. Public results contain only authorized/cancelled or fixed error codes.

Concrete bounds:16KiB UTF-8 bytes per JSON frame,64KiB maximum queued output,4096 UTF-8 bytes per answer, one pending prompt,180-second prompt deadline and1200-second whole owner-session deadline. These are transport safety limits, not changes to native device polling. Enforce `device_code` server-side for the native browser/device selection; hiding the browser option in the client alone is insufficient. Restore terminal input/echo on success, error, signal, withdrawal and disconnect. Protocol decline is fixed sanitized cancellation unless the exact native decline class identity is imported and proven; do not simulate that class by name.

## Failure behavior

Notify is synchronous. Catch serialization/write errors inside it, abort using a fixed safe reason, and do not throw challenge-bearing data into the authorization logger. Prompt always returns a Promise, handles its own signal and overall cancellation, and rejects only fixed sanitized errors. Use native decline semantics only when proven; do not invent an error class identity. Disconnect, cancel and disposal abort and reject pending prompts. No raw error messages, stacks, causes, server responses or challenge/input values in logs or evidence. Do not attach throwing settlement listeners.

The native seam races cancellation without proving the provider flow has finished unwinding. A cancelled response must not be reported as proof of no late native credential write. Keep the single-attempt lock spent and do not retry. Report the limitation; do not wrap or replace shared credential writes to disguise it. Authorized status must come from this attempt's native committed-record outcome, not preexisting state.
